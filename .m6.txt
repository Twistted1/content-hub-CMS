Review the tier cap, fix a misleading log, and make one Stripe price table

Tier-cap review (no behaviour change). The tier-aware AI budget logic is sound and
its coverage is good, including the case that matters most: a pro subscription
whose end_date has already passed resolving to free, so a cancellation the webhook
has not yet caught up on cannot keep granting a paid allowance. Missing row, read
error and expired end_date all fail conservatively.

Found and fixed a real bug in it: three log messages instructed an operator to
apply migration 20261019000001_add_ai_usage_log.sql, a file that was DELETED as a
duplicate and never applied. Anyone hitting "AI SPEND IS NOT BEING ENFORCED" would
have hunted for a migration that does not exist, at the exact moment they needed a
correct instruction. Now points at 20261016014921_add_ai_usage_tracking.sql.

Stripe price IDs consolidated from three independent copies into
_shared/stripePrices.ts, read by create-checkout, check-subscription and
stripe-webhook. The literals were not the bug, the three copies were: updating two
of the three left the third disagreeing, and the failure was silent -
create-checkout would take the customer's money and then stripe-webhook's
resolveTier would resolve the now-unrecognised price to "free" and downgrade them
with no error anywhere. The reverse map is now derived from the forward map, so a
plan cannot exist in one and not the other.

Env-overridable and safe by default: STRIPE_PRICE_STARTER_MONTHLY,
STRIPE_PRICE_STARTER_YEARLY, STRIPE_PRICE_PRO_MONTHLY, STRIPE_PRICE_PRO_YEARLY.
Unset means the built-in values, so behaviour is unchanged until someone opts in,
and a second deployment sets four secrets instead of editing code. Deliberately
not memoised: this project has already been bitten by a warm edge function holding
a stale secret (the STRIPE_WEBHOOK_SECRET incident) and a cached price table would
reintroduce exactly that. An unrecognised price is still resolved to "free" - the
safe direction - but now logs the priceId and productId, and a duplicate mapping
is reported rather than silently keeping whichever won the iteration order.

8 new tests pin the properties that make the consolidation worth having: the
reverse map matches the forward map, each plan/interval maps to a distinct price,
an override is followed by both maps, overrides are trimmed (a secret pasted with
a trailing newline is a real failure), an empty override counts as unset,
duplicates are reported, and the legacy product IDs are not accidentally emptied.
buildStripePriceTable takes the env lookup as a parameter, so it is a pure
function testable without a Deno runtime.

Also adds docs/OPEN_DECISIONS.md: everything still outstanding, split into
decisions only the owner can make, actions needing access an agent does not have,
and optional engineering - so the remaining to-do lives in the repo rather than in
a chat log. Flags one operational risk found during the review: a missing
subscriptions row resolves to free ($1/month) and schedule-from-templates invokes
content-pipeline as the automation owner, so an owner without a subscription row
would have automated generation stop after about a dollar of spend.

Verified: tsc 0, eslint 0 errors (293 warnings), 165 passed / 1 skipped (was 157),
build clean, and no leftover references to the old inline price maps in any edge
function. Requires redeploying create-checkout, check-subscription and
stripe-webhook; safe on its own since behaviour is identical until the
STRIPE_PRICE_* secrets are set.
